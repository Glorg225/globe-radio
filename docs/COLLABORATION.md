# Globe Radio — как работать вдвоём

Документ для второго разработчика (и его ИИ-агента). Прочитать один раз целиком, дальше — как справочник.

## 0. Начать здесь (10 минут)
1. **Доступ.** Сообщите владельцу проекта свой логин на GitHub — он добавит вас в репозиторий (Settings → Collaborators). Примите приглашение из письма или на https://github.com/Glorg225/globe-radio/invitations. Без этого вы сможете читать и запускать код, но не отправлять свои ветки.
2. **Запуск.** Выполните команды из раздела 3 — `npm test` должен пройти, сайт должен открыться на http://localhost:5173.
3. **Прочитать:** этот файл целиком, затем `README.md`, ТЗ `docs/02_tz.md` (по диагонали) и дизайн `docs/03_design.md` — перед любой правкой интерфейса.
4. **Выбрать задачу** с меткой `for: dev2`: https://github.com/Glorg225/globe-radio/issues?q=is%3Aopen+label%3A%22for%3A+dev2%22 — назначить на себя, поставить метку `in progress`, написать в задаче «Беру».
5. **Работать по разделу 5** и сдать pull request.

## 2. Что это за проект
3D-глобус с живыми радиостанциями мира: нажал на точку — слушаешь эфир города, рядом карточка места. Режим «Учу язык», поиск, избранное, «Удиви меня», «Поделиться», таймер сна, установка на телефон (PWA).
Продакшен — **только английский** (название **Globe Radio**). Трафик планируется на 90 % из Google, поэтому **SEO — обязательное требование** к любой новой странице.

**Стек:** Vite + TypeScript без фреймворка, Vitest + jsdom, globe.gl (3D), d3 (плоская карта), hls.js, vite-plugin-pwa. Хостинг — GitHub Pages, публикация — GitHub Actions (`.github/workflows/deploy.yml`), раз в сутки обновляется снимок станций из Radio Browser.

## 3. Запуск
Нужен Node.js 22+ и git.
```bash
git clone https://github.com/Glorg225/globe-radio.git
cd globe-radio
npm install
npm run snapshot   # скачать станции в public/data/ (2–3 мин, папка не в git)
npm run dev        # http://localhost:5173
npm test           # все тесты (должны быть зелёными до и после вашей работы)
npm run build      # проверка типов + сборка в dist/
npm run preview    # собранный сайт с service worker: http://localhost:4173
```
Если `npm run snapshot` не может достучаться до Radio Browser — повторить позже.

## 4. Как устроен код
| Папка | Что внутри |
|---|---|
| `src/app/` | `main.ts` — сборка зависимостей; `app.ts` — связка всего приложения; `config.ts` — языки |
| `src/data/` | формат снимка (места, станции по странам), языки, справочник городов |
| `src/map/` | 3D-глобус и плоская карта за общим интерфейсом `MapView`, кластеры |
| `src/player/` | плеер (потоки, HLS, тайм-ауты, чёрный список), «Следующая рядом», «Удиви меня», таймер сна |
| `src/place-card/` | карточка места: время, Википедия, флаг |
| `src/learn/` | режим «Учу язык» |
| `src/search/`, `src/library/`, `src/share/` | поиск, избранное/история, ссылки «Поделиться» |
| `src/pwa/` | установка, состояние сети, обновления |
| `src/ui/` | разметка и стили (`tokens.css` — все цвета; `mobile.css` — телефон и планшет) |
| `locales/` | тексты интерфейса (`en.json` — продакшен, `ru.json` — для тестов) |
| `scripts/` | снимок станций, справочник, иконки, картинка-превью |
| `tests/` | тесты (Vitest), по одному файлу на модуль |

**Правила кода (проверяются тестами или ревью):**
- В `src/` нет строк интерфейса — только ключи из `locales/*.json`. Комментарии — по-английски.
- Данные станций (названия, теги) попадают в страницу только через `textContent` или `escapeHtml` — это чужие данные.
- Цвета — только переменные из `src/ui/tokens.css`.
- Сначала тест, потом код (TDD). Любая ошибка → сначала тест, который её ловит.
- Каждая новая страница — с `title`, `description`, canonical, понятным H1 (SEO).

## 5. Как мы не делаем одно и то же
**Главное правило: работа начинается только с задачи (Issue), назначенной на вас.**

1. **Найти задачу.** Открытые задачи — в [Issues](https://github.com/Glorg225/globe-radio/issues). Метки:
   - `for: dev2` — предназначены вам;
   - `for: claude` — делает Claude (ИИ-агент владельца проекта), их не брать;
   - `for: owner` — делает владелец проекта руками (аккаунты Google, домен);
   - `in progress` — кто-то уже работает; смотреть поле **Assignees**.
2. **Взять задачу.** Назначить на себя (Assignees), поставить `in progress`, написать в задаче комментарий «Беру, план: …». Если задачи нет — создать её и так же назначить.
3. **Ветка.** От свежего `main`: `git checkout main && git pull && git checkout -b 12-short-name` (номер задачи + пара слов).
4. **Работа.** Маленькими коммитами, тесты зелёные.
5. **Pull request в `main`.** В описании: `Closes #12`, что сделано, как проверено. Добавить строку в `CHANGELOG.md`.
6. **Вливание.** После зелёных тестов и просмотра владельцем (или второй стороной). Задача закроется сама. **Напрямую в `main` не коммитить.**

**Чтобы не было конфликтов:**
- Перед началом посмотреть открытые PR и задачи `in progress`: если они трогают те же файлы — договориться в комментариях задачи.
- Тяжёлые для конфликтов файлы: `src/app/app.ts`, `src/ui/shell.ts`, `locales/*.json`, `src/ui/mobile.css`. Правки в них — небольшие и быстро вливать.
- Новые тексты в `locales/*.json` — добавлять **в конец** файла (меньше конфликтов).
- Перед PR подтянуть свежий `main`: `git pull origin main` (или rebase), прогнать `npm test` и `npm run build`.

## 6. Как узнать, кто что сделал
- **Issues** — что запланировано и кто взял.
- **Pull requests** — что сделано и как проверено (описание + обсуждение).
- **`CHANGELOG.md`** — короткая лента изменений, по строке на PR.
- **Ветки** — `git fetch && git branch -r`: видно, что сейчас в работе.
- Вопросы друг другу — комментариями в задаче или PR (а не в личных сообщениях), чтобы история осталась в одном месте и её видели ИИ-агенты.

## 7. Если работаете с ИИ-агентом (Claude Code и др.)
- Мы используем **Superpowers** (плагин для Claude Code): дизайн → спецификация (`docs/superpowers/specs/`) → план (`docs/superpowers/plans/`) → выполнение по шагам с тестами → общий обзор ветки → PR. Для крупной задачи — тот же порядок.
- Дайте агенту прочитать этот файл, `README.md`, ТЗ и нужную спецификацию.
- Попросите агента перед началом проверить открытые Issues/PR (через `gh issue list`, `gh pr list`), а после — оставить комментарий в задаче с итогом.
- Агент не должен коммитить в `main`, удалять ветки других людей и менять настройки репозитория.

## 8. Публикация
Вливание PR в `main` → GitHub Actions собирает сайт (со свежим снимком станций) и публикует за 2–3 минуты. Ошибка сборки видна в [Actions](https://github.com/Glorg225/globe-radio/actions); повторить — **Re-run jobs**. Подробнее — `README.md`, раздел «Как выложить обновление самому».
